# Group 19 NIDS Analytics Dashboard Guide

**Hosted app:** https://group19-network-intrusion-detection.streamlit.app/  
**Repository:** https://github.com/adugnaNecho/Group19-network-intrusion-detection

## Dashboard sections

The Streamlit application now has three tabs: **CSV Prediction**, **Analytics Dashboard**, and **About & Limitations**.

### 1. Benchmark model performance

The dashboard reads `artifacts/evaluation.json`, generated by `python train_model.py`, and presents validation and independent KDDTest+ metrics:

- Accuracy
- Macro precision
- Macro recall
- Macro F1
- Per-class precision, recall, F1 and support when present in the evaluation artifact
- The measured 5 × 5 KDDTest+ confusion matrix
- One-versus-rest false-positive rates when present

If `evaluation.json` is missing or invalid, the dashboard uses only the latest values transcribed from the successful training command supplied by the project group. That fallback contains aggregate validation/test metrics and independent-test class recall only. It does **not** invent a confusion matrix, class precision/F1, or false-positive rates; those panels explain when the source evidence is unavailable.

### 2. Uploaded-record analytics

After uploading a CSV and selecting **Predict intrusion class** in the CSV Prediction tab, the dashboard summarizes that same upload:

- Predicted class counts across Normal, DoS, Probe, U2R and R2L
- Predicted threat-severity counts (Low, Medium, High and Critical)
- A Normal-versus-predicted-attack source-byte profile (groups are model predictions, not ground truth)
- Source/destination byte features and connection counts across uploaded record order
- Maximum class probability for each record
- Download of the current prediction results

The network traffic feature chart is plotted by **record order**, not time. NSL-KDD input features do not contain timestamps. Source and destination byte counts are transformed using `log10(value + 1)` only for chart readability; this does not alter model inputs or predictions. The displayed maximum class probability is not claimed to be calibrated.

## Reproducible setup

The dashboard adds `nids_dashboard.py` at the repository root. No extra charting dependency is required; charts use Streamlit's built-in chart components.

```bash
python -m pip install -r requirements.txt
python -m pip install -r requirements-dev.txt
python -m pytest -q
streamlit run app.py
```

Make sure these exported files are in the repository under `artifacts/`:

- `group19_final_nids_random_forest_pipeline.joblib`
- `group19_nids_class_mapping.json`
- `evaluation.json`
- `model.sha256`

The model must be the trusted artifact created by this project's training script. Never load a `.joblib` file from an untrusted source.

## Interpretation and limitations

The latest group-reported run achieved 74.62% accuracy and 51.51% Macro F1 on independent KDDTest+. Recall was 8.96% for U2R and 7.20% for R2L. The dashboard should make these weaknesses visible rather than relying on overall accuracy alone. This is a benchmark-based research prototype for uploaded NSL-KDD-style connection records. It does not capture live packets, block traffic, or operate a production monitoring service.
