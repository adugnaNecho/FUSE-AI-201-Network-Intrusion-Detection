GROUP 19 NIDS ANALYTICS DASHBOARD UPDATE

1. Extract this ZIP over your existing Group19_NIDS_Module6_Prototype folder.
   Allow the included files to overwrite existing files when prompted.
   Do not delete or replace your local artifacts/*.joblib model.

2. The important new/updated files are:
   - app.py                         Updated Streamlit UI with three tabs
   - nids_dashboard.py              Analytics and evaluation helper functions
   - tests/test_dashboard.py        Dashboard unit tests
   - docs/analytics_dashboard_guide.md
   - README.md and supporting test/checklist/manifest documentation

3. In Git Bash, from the project folder, activate your existing environment:
   source .venv/Scripts/activate

4. Run the updated test suite:
   python -m pytest -q
   Expected in this prepared update: 28 passed.

5. Run locally:
   streamlit run app.py

6. Review both tabs:
   - CSV Prediction: upload a 41-feature CSV and click Predict intrusion class.
   - Analytics Dashboard: review KDDTest+ benchmark cards, validation/test comparison,
     class-wise metrics, 5x5 confusion matrix (when evaluation.json is present),
     one-versus-rest FPR, uploaded class/severity distributions, traffic feature
     profiles and confidence display. The grouped comparison uses a 0–100% axis.
     Class metrics, recall/FPR charts and confusion-matrix axes share the order
     Normal, DoS, Probe, U2R, R2L. Support counts are integers; FPR is percent-formatted.

DATA AND CLAIMS SAFEGUARDS
- Benchmark metrics and the confusion matrix come from artifacts/evaluation.json,
  which is generated by train_model.py.
- If that file is missing, the app uses only the reported validation/test summary
  and class recall values. It does not fabricate confusion matrices or metrics.
- Uploaded-record charts summarize model predictions, not verified ground-truth labels.
- The NSL-KDD records have no timestamp field in the required 41-feature schema;
  traffic plots use record order, not a time axis.
- The dashboard is for research demonstration, not production network monitoring.


Latest dashboard refinement (class presentation):
- Support counts are formatted as integers in the class-wise table.
- Recall and one-versus-rest false-positive rate charts use percentage axes.
- Class metrics, recall bars, false-positive-rate bars and confusion-matrix rows/columns use the fixed order Normal, DoS, Probe, U2R, R2L.
- The validation-versus-KDDTest+ comparison remains grouped, with a 0–100% axis.
